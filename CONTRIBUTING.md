# Contributing

Thanks for helping improve MascotRL.

## Before you start

- Run `pytest -q -m "not slow"` locally before opening a PR. CI must stay green.
- Open an issue before large structural changes (new packages, eval protocol edits, wide refactors).
- One concern per pull request. Unsolicited sweeping refactors will be closed.
- Match existing naming, formatting, and test style in the files you touch.

## Pull requests

- Link an issue for non-trivial work.
- Include or update tests when behaviour changes.
- Do not commit secrets, `.env`, or vendor datasets.

## Good first issues

Maintainers may label suitable tickets `good first issue`. Use that label to self-select; do not expect every open issue to be beginner-sized.

## Response time

Issues are read. A reply may take several days depending on load.

## Code of conduct

See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Report conduct concerns via GitHub private vulnerability reporting or a direct message to [@zauberstern](https://github.com/zauberstern).
